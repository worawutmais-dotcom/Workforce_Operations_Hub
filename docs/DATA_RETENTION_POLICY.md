# BVN Package — นโยบายข้อมูลแบบประหยัดพื้นที่

## สิ่งที่เก็บใน Supabase

| ข้อมูล | นโยบาย |
|---|---|
| ทะเบียนพนักงาน | เก็บจนกว่าจะปิดใช้งาน/ลบโดย Admin |
| เวลาเช็กอิน/เช็กเอาต์ | เก็บ 6 เดือนล่าสุด |
| คำขอที่ยังรออนุมัติ | เก็บจนกว่าจะตัดสินใจ |
| token/session ที่ใช้งานได้ | เก็บเท่าที่จำเป็นต่อการ login |
| ข้อมูลบริษัท, หัวบิล, โลโก้ | เก็บต่อเนื่อง |
| Audit log | ไม่บันทึกลงฐานข้อมูล |

## สิ่งที่ล้างอัตโนมัติ/อย่างประหยัด

- Admin session หมดอายุ หรือ token ที่ถูก revoke: ลบภายในประมาณ 1 วัน
- คำขอรีเซ็ตรหัสผ่านและคำขอยืนยันตัวตนที่จบแล้ว: ลบหลัง 7 วัน
- ไฟล์โลโก้เก่า: เมื่ออัปโหลดโลโก้ใหม่ ระบบลบไฟล์ก่อนหน้าออกจาก Storage
- Audit log: หยุดสร้างรายการใหม่ และ `patch_minimal_data_mode.sql` ลบของเดิม

## Archive เวลาเข้าออก 6 เดือน

1. Owner เปิด `ตั้งค่า → เก็บเวลาเช็กอิน/เอาต์ 6 เดือน → สร้าง Archive`
2. ระบบสร้าง JSON และดาวน์โหลดลงเครื่อง ไม่เก็บสำเนา archive ไว้ใน Supabase
3. Owner เลือกไฟล์เดิมกลับมา ระบบตรวจ SHA-256 checksum
4. Owner กรอกรหัสผ่านและพิมพ์ `PURGE 6 MONTHS`
5. ระบบลบเฉพาะ `attendance_log` ที่เก่ากว่า cutoff ที่อยู่ใน archive

การล้างจะถูกปฏิเสธหากไม่มี archive ที่ตรวจ checksum ผ่านภายใน 30 นาที

## อ่านไฟล์ย้อนหลัง

หน้า `อ่านไฟล์ Archive` เปิด JSON จากเครื่องโดยตรงและแสดงรายการเวลาเช็กอิน/เอาต์ได้สูงสุด 500 แถวต่อครั้ง โดยไม่อัปโหลดกลับเข้า Supabase

## ข้อเท็จจริงเรื่อง Memory commitment

กราฟ `Memory commitment` ของ Supabase คือหน่วยความจำที่ compute/database process ใช้ ไม่ใช่ขนาดตารางอย่างเดียว การล้าง audit log และข้อมูลเก่าช่วยลด disk, index และ cache pressure แต่ไม่รับประกันว่า committed memory จะลดทันที ต้องดู Table/Database size และถ้า memory ยังสูงให้ตรวจ query ที่กิน RAM, connection pool และขนาด compute instance เพิ่มเติม
