# Employee APK — Work Identity Profile

## Intent

ปรับแท็บ `บัญชี` ของพนักงานให้เป็นหน้าที่ตอบได้ทันทีว่า บัญชีใช้งานได้หรือไม่,
ข้อมูลส่วนตัวครบหรือยัง, ต้องลงเวลาตามพิกัดหรือไม่ และต้องทำอะไรต่อ โดยไม่เปลี่ยน
API, กติกา GPS หรือสิทธิ์ของผู้ดูแลเดิม

## Selected approach

ผู้ใช้เลือก **แบบ 2: Work Identity** จาก mockup วันที่ 25 พฤศจิกายน 2569

- ส่วนหัว: ชื่อ, รหัสพนักงาน, ตำแหน่ง
- สถานะสำคัญ 2 ช่อง: สถานะบัญชี และสถานะการยืนยันข้อมูล
- แถบนโยบายการลงเวลา: GPS/พิกัดที่ต้องใช้ พร้อมคำอธิบายสั้น
- Action ตามลำดับงาน: ข้อมูลส่วนตัว, เงินล่วงหน้า, ความปลอดภัยบัญชี, ออกจากระบบ

## Goals

- คนทำงานหน้าร้านอ่านข้อความได้เร็วโดยไม่ต้องตีความคำทางเทคนิค
- งานค้างด้านข้อมูลส่วนตัวเด่นกว่างานที่ทำเสร็จแล้ว
- สื่อสาร GPS เป็น “นโยบายการลงเวลา” ไม่ใช่การตั้งค่าที่พนักงานแก้เองได้
- ปุ่มอันตราย (ออกจากระบบ) แยกจาก action ปกติอย่างชัดเจน

## Non-goals

- ไม่เพิ่มข้อมูลส่วนบุคคลใหม่หรือส่งข้อมูลไป Supabase เพิ่ม
- ไม่เปลี่ยน endpoint `employee_profile` / `employee_identity_profile`
- ไม่เปลี่ยนพฤติกรรม GPS, การเปลี่ยนรหัส, เงินล่วงหน้า หรือ logout

## Implementation

1. ปรับ `_Account` ใน `employee_mobile/lib/main.dart` เป็น Work Identity layout
2. แสดง status จากข้อมูลเดิม: `profileNeedsUpdate`, identity pending/completion และ locationRequired
3. คง dialog และ callback เดิมทั้งหมด เพื่อไม่ให้ flow บัญชีแตก
4. ใช้ token สี/ตัวอักษรใน `theme.dart` เท่านั้น ไม่ hard-code theme ใหม่ในหน้า

## QA / acceptance

- Flutter analyze และ widget tests ผ่าน
- หน้ากว้างแคบไม่ overflow
- สถานะ “ข้อมูลไม่ครบ”, “รอตรวจ”, และ “ครบแล้ว” ต่างกันชัดเจน
- GPS เปิด/ไม่บังคับต่างกันชัดเจน
- แตะข้อมูลส่วนตัว, เงินล่วงหน้า, เปลี่ยนรหัส, ขอรีเซ็ต และ logout ยังเรียก flow เดิม

## Follow-up product gaps

- ต้องทดสอบบนอุปกรณ์จริงสำหรับตัวอักษรไทย, ขนาดแตะ และ permission GPS
- หากจะเพิ่มสลิปหรือเอกสารพนักงานภายหลัง ให้เพิ่มเป็น action ใหม่ใต้ `บัญชี` ไม่ปนกับสถานะ identity
